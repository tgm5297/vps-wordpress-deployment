# VPS搭建网站：从选服务器到上线 WordPress，域名解析、HTTPS 和日常维护一次理清

用 VPS 搭建网站，真正费时间的通常不是买服务器，而是把几个环节接起来：准备域名、安装网站环境、上传或安装程序、配置 HTTPS，再确保服务器不会因为一次误操作就失联。下面以常见的 WordPress 网站为例，按实际部署顺序说明。命令部分以 Ubuntu 为例；如果使用其他系统，软件包和操作方式可能不同。

## VPS 建站前，先准备好这几样

开始之前，确认你有：

- **VPS 的公网 IP 地址**和服务器登录方式。
- **域名**，以及能修改 DNS 记录的域名管理账号。
- **SSH 客户端**。macOS 和 Linux 可用终端；Windows 可使用内置 OpenSSH 或其他 SSH 工具。
- **网站程序**。本文按 WordPress 说明；静态站点不需要 PHP 和数据库。
- **备份位置**。至少提前想好数据库和网站文件要备份到哪里，不能只把备份留在同一台 VPS 上。

还要先决定访问者主要在哪里。机房位置会影响访问延迟，不能只看套餐价格或“带宽”数字。若面向中国大陆访问，海外 VPS 的线路表现需要结合目标用户的运营商和地区评估；不能仅凭机房名称推断所有访问者都会快。

如果使用中国大陆服务器，域名和网站可能涉及备案等要求；具体以服务器提供商和主管部门的当前规定为准。选择海外节点并不自动解决所有合规、访问速度或服务支持问题。

## VPS 搭建网站的实际顺序

整体流程可以记成：

1. 购买 VPS 并选择操作系统。
2. SSH 登录，完成系统更新和基础安全设置。
3. 安装 Web 服务器、PHP 和数据库。
4. 部署 WordPress 并创建数据库。
5. 把域名解析到 VPS 的公网 IP。
6. 配置 HTTPS，检查网站和后台。
7. 设置更新、备份和监控。

这几步有先后关系。比如域名还没解析到服务器时，使用 HTTP-01 方式申请证书通常无法完成验证；防火墙若提前封掉 SSH 端口，也可能把自己挡在服务器外面。

## 第一步：购买 VPS 并登录

下单时选择适合的机房和操作系统。BandwagonHost 的官网列出 Ubuntu、Debian、AlmaLinux、RockyLinux 等系统选项；如果按本文命令操作，选择 Ubuntu 会更容易对应。套餐订单和可选机房请在购买页面确认。

系统部署完成后，记录公网 IP、登录用户名和初始认证信息。用 SSH 登录时，第一次连接会提示确认服务器主机密钥；应核对连接目标确实是自己的服务器，再继续。

登录后先更新系统：

bash
sudo apt update
sudo apt upgrade


建议使用日常管理账号和 SSH 密钥，而不是长期依赖 root 密码登录。修改 SSH 配置前，先确认密钥登录正常，并保留当前会话；否则配置错误时，可能需要通过服务商的紧急控制台恢复访问。

## 第二步：安装网站运行环境

WordPress 需要 Web 服务器、PHP 和 MySQL 或 MariaDB 数据库。WordPress 官方当前建议 PHP 8.3 或更新版本、MySQL 8.0 或更新版本，或 MariaDB 10.11 或更新版本，并要求支持 HTTPS；Nginx 和 Apache 都是官方推荐的 Web 服务器。安装前应核对所选系统软件源中的版本是否满足要求。

如果不熟悉命令行，可以考虑使用服务器管理面板来安装运行环境。不过，面板只是管理工具，并不会替代补丁更新、账号保护和备份。还要确认面板本身的安装来源可靠，并避免把管理端口不加限制地暴露到公网。

无论使用面板还是手动安装，建站环境都要包含：

- Nginx 或 Apache，用来接收网页请求；
- PHP 及 WordPress 所需扩展；
- MySQL 或 MariaDB 数据库；
- 一个单独的数据库和数据库用户，供该 WordPress 站点使用。

不要让 WordPress 直接使用数据库 root 账号。为网站创建独立数据库用户，并只授予该站点需要的权限。这样即使应用配置泄漏，数据库账号的权限范围也更容易控制。

## 第三步：创建站点并安装 WordPress

环境就绪后，按所用面板或服务器配置建立站点目录，并将域名填入站点配置。再创建数据库、数据库用户和强密码，保存数据库名称、用户名和密码，后续安装 WordPress 时会用到。

WordPress 可以通过安装器部署，也可以按官方手动安装文档下载程序、解压并配置数据库连接。安装完成后，访问域名，根据页面提示设置站点标题、管理员账号和密码。管理员用户名不要使用容易猜到的常见默认值；密码也不要与邮箱或其他服务共用。

安装后先检查三件事：网站首页能否打开、后台能否登录、文章页面是否能正常加载。之后再安装主题和插件。插件越多，更新和兼容问题越难排查；只安装确实需要的功能，并记录每个插件的用途。

## 第四步：把域名解析到 VPS

在域名服务商的 DNS 管理页面添加解析记录：

- `A` 记录：将主域名指向 VPS 的 IPv4 地址。
- `AAAA` 记录：只有服务器已正确配置 IPv6 时才添加。
- `www` 子域名：通常可以用 `CNAME` 指向主域名，也可以按实际 DNS 设置添加相应记录。

如果 `AAAA` 记录指向了错误或未配置的 IPv6 地址，部分用户可能会访问失败。别因为 DNS 页面允许填写 IPv6，就把它当作必须填写的项目。完成修改后，等待 DNS 更新，再用浏览器检查域名是否到达预期服务器。

## 第五步：开放必要端口并配置 HTTPS

网站通常要能接收 HTTP 和 HTTPS 请求。Ubuntu 的 UFW 是其默认防火墙管理工具之一；启用防火墙前，应先允许 SSH 登录所用端口，并确认规则适用于你的实际 SSH 端口。否则，启用规则后可能无法再次连接。Ubuntu 文档提供了 UFW 管理和开放端口的说明。

至少要检查：

- SSH 管理端口可以从你需要的位置访问；
- HTTP 的 80 端口和 HTTPS 的 443 端口可以对外访问；
- 不需要公网访问的数据库端口没有开放给所有来源。

域名解析生效、Web 服务能响应后，再通过服务器上的证书管理工具申请 TLS 证书，并配置 HTTP 跳转到 HTTPS。Let’s Encrypt 的 HTTP-01 验证需要从公网访问服务器上的验证文件，因此一般需要让 80 端口可达；如果不能开放该端口，应了解 DNS-01 等替代验证方式。

证书配置完成后，用浏览器分别检查 `https://你的域名` 和 `https://www.你的域名`（如果启用了 www），确认最终访问的是你指定的主域名，页面没有证书错误，WordPress 后台和图片也能通过 HTTPS 加载。

## 上线前别漏掉的维护事项

网站能打开，只代表部署流程走通了；后面还要有人照看。VPS 是自主管理型服务，系统和网站的日常维护不能只寄希望于机房监控。

- **定期更新系统、WordPress 核心、主题和插件。** 更新前先备份；对重要站点，可以先在测试环境检查兼容性。
- **备份数据库和网站文件。** 备份应存放在 VPS 之外，并定期确认文件能够恢复。只看到“备份成功”提示，不等于真的验证过恢复流程。
- **检查磁盘、内存和流量使用。** WordPress 备份、日志和图片都可能逐渐占用空间；接近资源上限时，网站未必会优雅地提醒你。
- **保护管理账号和 SSH。** 使用强密码或密钥，限制不必要的登录入口，避免公开管理面板端口。
- **保留错误日志。** 网站出现 502、数据库连接失败或证书续期异常时，日志通常比反复重启服务更能说明问题。

## 常见问题

### 没有 Linux 经验，能用 VPS 搭建网站吗？

可以，但要准备好学习服务器管理，或选择管理面板降低命令行操作量。VPS 不像普通托管主机那样把环境维护全部包办；系统更新、防火墙、备份和故障排查仍由站长负责。如果只想专心发布内容、不想管理服务器，托管型 WordPress 或虚拟主机可能更省心。

### 一台 VPS 能放多个网站吗？

可以通过 Web 服务器的虚拟主机配置，让不同域名指向不同站点目录。不过，多个网站会共享 CPU、内存、磁盘和网络资源，也会增加更新、权限和备份的管理复杂度。先让一个站点稳定运行，再添加第二个，问题更容易定位。

### 买完 VPS 后网站会自动上线吗？

不会。VPS 提供服务器资源和系统管理能力，网站仍需安装程序、配置域名和 Web 服务。BandwagonHost 的页面明确将其服务描述为 self-managed，并提供 KiwiVM 控制面板；这不等同于托管建站服务。

### VPS 建站需要单独购买域名吗？

需要有一个域名才能通过容易记忆的网址访问网站，也可以先用 IP 测试 Web 服务是否响应。域名注册、DNS 管理和 VPS 通常是不同环节，域名费用不包含在上述 VPS 套餐价格中。
